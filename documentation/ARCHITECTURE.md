# Runtime architecture

## Components and ownership

PocketAgent 0.2.0 development has a native Windows WPF desktop/server app and a native Android client built with Android platform widgets. There is no browser client or WebView. The desktop embeds an ASP.NET Core relay, owns one local Codex app-server subprocess over standard input/output, and stores local metadata in SQLite. Android uses foreground HTTPS snapshot polling. The retained SignalR API is compatible with earlier relay consumers but is not required by either native UI.

Only conversations created by PocketAgent and registered in this host's runtime database are exposed. Existing IDE-owned sessions are not attached. The configured repository supplies the default folder; each new conversation can select a different existing local directory. A phone can pair with several different desktop hosts. Provider execution, repository access, provider credentials, and provider-owned transcript history remain on the desktop.

Desktop administration calls local services in-process. The network API exposes paired conversation operations, usage, schedules, and folder selection, not host permission settings, executable settings, pairing-code generation, or device administration. All paired devices act as the same desktop owner across the host's PocketAgent conversations; separate user roles are not implemented. The approved multi-folder expansion allows authenticated devices to browse directory names and select existing folders on local drives accessible to the desktop account. This is owner access, not a per-repository access boundary. Directory browsing does not return file contents, create folders, or accept network/UNC/device paths. Conversation folders are immutable after creation and never rewrite the host's default folder. Provider sandbox/approval selection remains desktop-owned; workspace-write roots must use the selected conversation folder on every turn.

## Provider discovery and permissions

`CodexExecutableResolver` prioritizes an explicit executable override, then the highest installed stable VS Code `openai.chatgpt-*` extension's architecture-matching native binary, then a native CLI on PATH/npm locations. The default extension root is the current user's `.vscode/extensions`; `CodexExtensionsDirectory` can override it. No extension files are copied, changed, or redistributed. An already running provider process keeps its selected executable until restart. The model is never silently replaced.

`HostSettings.PermissionMode` is a desktop-owned startup setting:

| Value | Behavior |
| --- | --- |
| `inherit` | Omit policy overrides and use Codex settings. Default. |
| `ask` | Request workspace-write with restricted network access and on-request approvals. |
| `full-access` | Request danger-full-access and approval policy never. |

`CodexPermissions` applies an explicit selection to thread start/resume and each new turn. Steering retains the active turn's policy. Global Codex configuration, model, and reviewer are not rewritten. Managed provider restrictions remain authoritative. Provider rejection is surfaced without falling back to a weaker mode. The conversation snapshot distinguishes the selected mode from sandbox/approval fields reported by the provider. Old transcript reads do not resume execution or establish current permissions.

The native desktop selector is disabled while the host runs. Stop, save, and restart to change the mode. This changes PocketAgent-owned conversations, not a separate parent agent, IDE, or terminal session. Permissions determine command access; repository instruction files can still require a conversational planning approval.

## Authentication and device access

The desktop's QR and copied pairing string contain the same versioned payload: an exact HTTPS origin, SHA-256 of SubjectPublicKeyInfo, and a random 256-bit ticket. It is an out-of-band trust transfer from the user's desktop. No pin is fetched/trusted from an unauthenticated network response. Android accepts a strict four-field URI (no duplicates/fragments/unknown version), verifies the pinned leaf key, validity, server-auth purpose and hostname, then exchanges the ticket at /api/devices/pair. There is no second code. New tickets expire in ten minutes, authorize once, and rotation invalidates older tickets. A photo/copy of an unused ticket is a temporary credential; no private key/provider credential is in the payload.

PairingCode retains its six-digit API-compatible credential for older headless clients, but the native UI uses scan/paste only. Both credentials share one consumed/expiry state and rate caps. Tickets are never exposed through a remote QR endpoint or normal logs. Bearer tokens remain random, unique per enrolled phone, SHA-256 hashed in SQLite, thirty-day expiry and individually revocable. All paired devices have the desktop owner's conversation access.

All protected operations authenticate on every request. Native mutations require `X-PocketAgent: 1`. Any supplied browser Origin must exactly match a configured origin; CORS is not enabled. The legacy cookie pairing/logout path remains for API compatibility checks, with HttpOnly, SameSite Strict and HTTPS Secure cookies. There is no browser UI behind it.

Android stores saved server names, origins and tokens in an AES-GCM encrypted vault using a non-exportable Android Keystore key. Tokens are tied to their exact origin; changing or adding an address requires pairing at that address. Redirects are rejected before credentials can be forwarded. Each host has separate selection, draft and uncertain-delivery state. Backups and device transfers exclude app data. Draft text is private app-local state and is not packaged. A revoked server returns to pairing without deleting other saved server connections.

## Network exposure and trust

The default runtime is the user's desktop. Direct internet uses an explicit private IPv4 listener and an advertised public IPv4 HTTPS authority, with one manually configured router port forward and Windows Firewall allowance. Public and internal ports may differ. Host/Origin checks accept only configured exact authorities, no arbitrary forwarded headers. CGNAT/double NAT are external setup constraints. IPv6 and automatic router mapping are not implemented. Public-IP discovery through ipify occurs only on explicit click; it is an isolated bounded credential-free setup lookup, not a conversation relay.

PeerCertificates provisions a self-signed RSA-3072 server certificate under DataDirectory/certificates/device/server.pfx, with a persistent identity.pem protected by owner-only directory ACLs. Atomic replacement prevents partial writes; missing/mismatched identity beside an existing certificate fails rather than silently rotating identity. The managed path is validated. The certificate has server-auth EKU, leaf constraints and SANs for listener/advertised address. Local startup/daily maintenance renews within thirty days of expiry with the same key and reloads the TLS context without interrupting agent work. Old certificates stay alive until host shutdown for in-flight handshakes. Runtime ownership is checked before startup/provisioning. Private keys never enter mobile artifacts.

Android PinnedTrust uses the scanned SPKI as its explicit trust anchor, checks the exact key, validity, leaf constraints and server-auth EKU, and preserves Android's standard hostname verification. This deliberate custom trust manager has a narrowly documented lint exception and real positive/negative TLS tests. Pinned ApiClient instances are immutable per origin/token/pin; no wrong-key-to-public-CA fallback or redirect is allowed. SessionStore stores pins with tokens inside the existing AES-GCM Keystore vault. Old saved connections without pins retain their earlier trust model until re-paired.

The phone needs no system CA installation. Let's Encrypt/ACME and its challenge listener/dependency were removed in 0.1.10; ports 80/443 and the user's Caddy host are outside this flow. Cloudflare connector support was removed earlier. These historical models do not define current setup. Legacy PublicOrigin API configuration remains compatible for explicit headless users but is not a desktop onboarding alternative.

ConnectivityDiagnostics connects to the local listener while verifying the public-IP identity, exact Host and metadata. It sends no credentials and makes no external reachability claim. With managed QR certificates it trusts the local leaf for the test; on the phone the scanned public key is the trust anchor. Router/cellular acceptance remains separate. A changed public IP requires provisioning a matching SAN and pairing at the changed origin; identity is retained, but tokens are never forwarded across origins.

On Windows, the desktop can create one explicitly approved inbound TCP port rule named `PocketAgent inbound TCP <port>`. The rule is port-based rather than tied to the versioned executable path, so replacing the desktop package does not create a new firewall exception. The rule is only requested for a non-loopback listener, requires UAC elevation once, and is not silently created or broadened by the app. Changing the configured listener port creates a separate rule for the new port; old rules are left for the user to remove.

## Conversations, steering and recovery

`Conversations` serializes state mutations per conversation; the host-wide gate only protects the state registry and event dispatch bookkeeping. Exactly one provider turn runs per conversation. Idle input starts a new turn; additional active input uses `turn/steer` with the sender's expected turn ID. A stale ID is rejected and never silently converted into a new turn. An unscoped second turn is rejected. Steering does not answer an approval, modify policy, or cancel work. Initial history hydration for reads runs outside the host-wide gate and concurrent reads of one conversation are deduplicated.

Both native clients leave the composer editable during submission and clear only the exact acknowledged draft. Every prompt submission carries a client-generated message ID through the relay receipt and scheduled queue; canonical user items echo that ID, so optimistic bubbles reconcile by identity rather than text whenever possible. Delivery states distinguish pending, accepted, queued and uncertain outcomes; uncertain native delivery is persisted per origin/conversation and requires the user to review before resubmitting. Typing after Send is preserved. Neither prompts nor approval decisions are automatically replayed. Reconnection refreshes authoritative state; phone disconnection does not stop desktop execution. Provider disconnect clears pending controls and requires a host restart.

Each conversation retains its working directory, optional selected model, and optional reasoning effort in SQLite. The host default is only a creation fallback. Create/resume/turn requests explicitly use the stored directory; workspace-write policy roots follow that directory. An idle conversation can select a model from the live, paginated provider catalog. It is sent on subsequent starts/resumes/turns without rewriting global Codex config or another conversation's model. Model-advertised reasoning efforts are offered per conversation and sent on `turn/start` as `effort`; clearing the setting uses the model default. Active, uncertain, or disconnected work blocks model changes; steering has no model/directory overrides. Scheduled messages use the model and reasoning selected at dispatch. Omitting a model during creation preserves Codex settings. Catalog presence is not proof of inference entitlement. The integration follows the [official Codex app-server documentation](https://learn.chatgpt.com/docs/app-server).

Archive is a reversible PocketAgent registry state, not provider history deletion. It removes the tab from all devices and is blocked during active/unconfirmed work or an in-flight scheduled dispatch. SQLite atomically marks the archive and cancels pending schedules. The scheduler cannot claim or requeue work for an archived conversation. Archived history is readable; mutation/send/schedule operations require restore. Restoring never requeues canceled jobs. An additive database migration preserves old conversation directories and device credentials; all conversations registered in the same runtime are available regardless of the current default directory.

Codex standard input/output/error streams explicitly use UTF-8. Native Windows launches otherwise can decode raw non-ASCII JSON using the Windows default encoding, corrupting punctuation before HTTP serialization. Android already reads/writes HTTP JSON with UTF-8. No heuristic character substitutions are applied. User messages have trailing-edge bubbles; assistant prose uses the plain transcript background in both apps. Local time grouping still applies.

Android transcript updates use coordinate scrolling rather than `ScrollView.fullScroll`, which can move focus to a newly added selectable message. Incoming output must preserve the composer's focus, cursor/selection, draft and keyboard state; polling must not refocus the composer if the user is interacting elsewhere. The focused native regression checks a draft and a cursor in its middle while a delayed assistant response arrives.

Desktop `Transcript` sets inherited `TextElement.Foreground` to light green `#C1DAA6`, preventing user/assistant/tool text and approval descriptions from inheriting the tab theme's black foreground. The desktop root and every major WPF surface now explicitly use the dark palette: the window/content grid, tab control and selected-content host, scroll viewers, dialogs, inputs, lists, popups, calendars and date pickers. The desktop root also applies the readable text color to static settings/device labels. This is scoped to the native app; explicit timestamp/error colors and control styles for buttons/text inputs take precedence. The transcript renderer keeps a bounded recent view (400 items and 300,000 characters) so a tool-heavy history cannot grow the WPF visual tree without limit. The relay snapshot is also bounded to the latest 200 items with text/detail caps and sets `historyTruncated`; both clients surface that older history is hidden. Provider hydration still retains the full provider walk until a future paginated history API is added. `tests/PocketAgent.DesktopChecks` renders the real native hierarchy with isolated settings and asserts effective brush values, dark rendered surfaces and the large-transcript budget; a plain source check would miss the inheritance problem.

Supported command/file approvals are restricted to available one-time decisions. Broader grants, unsupported host interactions and unknown provider fields are not automatically approved. Questions require explicit answers. Pending requests retain their original JSON-RPC and conversation identity; resolved requests cannot be answered again.

Codex owns transcripts. SQLite stores PocketAgent references, device hashes, timing metadata and schedules. Live message timestamps are persisted on first observation and restored from that metadata. Provider turn times support work durations, but are not invented as individual message times for older history. Unknown historical message times remain unknown. Turn starts/completions/durations are retained separately and surfaced as active elapsed time or completed work duration. Clients group adjacent chat times by local minute. Status/context controls remain between the scrolling transcript and composer. Session navigation uses top tabs.

## Desktop presentation

Native controls use explicit dark surfaces/light text; title-bar colors are requested via DWM on supported Windows versions. AppDialogs uses styled WPF confirmations with explicit Yes/non-approval dismissal. OS-owned folder pickers retain Windows theme behavior. The icon is generated from repository-owned vector geometry by Generate-Icon.ps1 and embedded in the executable. Settings displays the running version and executable path to distinguish old shortcuts.

Readability tests inspect effective brushes and rendered screen surfaces, but cannot prove every OS theme state on the user's display. The earlier theme claim exceeded that evidence. QR white quiet zones are deliberate for scan contrast. Pairing images/strings are cleared from the desktop view after expiry/consumption; they must not be logged or put in shared artifacts.

## Usage and scheduled messages

`ProviderUsage` reads `account/rateLimits/read` through the same provider connection and accepts rate-limit updates. It exposes only normalized remaining percentage, duration, reset time and availability. Account IDs, plan/credit details and upsell payloads stay private. Five-hour and weekly labels require reported 300-minute and 10080-minute windows; unsupported/missing data is shown as unavailable. Read results are briefly cached. No credits or earned resets are purchased/consumed by PocketAgent.

`ScheduledMessages.Send` checks known exhausted windows. A blocked prompt is persisted and acknowledged as queued, with the reported reset time or an explicit unknown-reset state. The latest reset among exhausted windows is used. A later provider `usageLimitExceeded` failure also defers an accepted prompt only when no work is known to have executed. It never automatically repeats partial work or an uncertain submission.

Manual schedules accept an explicit UTC timestamp converted from the client's chosen local date/time. Jobs have requested time, next attempt, reason and status. The worker waits for host readiness and an idle, confirmed conversation. Active turns and unanswered approvals postpone dispatch; schedules never become implicit steering or approval decisions. All registered folders share this host's queue; each job uses its own conversation's folder. Archived conversations cannot dispatch. Expired/revoked devices cancel their pending jobs; desktop-created jobs have no device expiry dependency.

Dispatch claims a pending job atomically in SQLite before contacting Codex. A confirmed acceptance marks it submitted; this is not a promise of successful agent completion. Known provider rejections become failed/pending as appropriate. Lost acknowledgements become uncertain. A host restart converts in-flight dispatching jobs to uncertain and never automatically replays them. A per-data-directory host lease is acquired before constructing/migrating the database, as well as before dispatch: attempting to start a new version while the old host runs must not change its schema. Missed due times are reconsidered when the desktop runs again. There are no OS wake timers or cloud workers: a sleeping/stopped desktop cannot dispatch.

## Build, distribution and change points

The Android reasoning picker consumes the relay's `supportedReasoningEfforts` as a string array (the relay normalizes provider objects). Treating those strings as JSON objects caused a main-thread NullPointerException immediately after changing models in 0.1.12. The 0.2.0 source fix validates entries and checks the selected conversation/model before displaying a delayed response. SmokeInstrumentation covers model change followed by selecting a reasoning level and returning to the default. The old debug APK reproduced the crash on the isolated emulator; the updated debug APK passed that flow on the isolated emulator. No release APK was produced for this change.

`scripts/Build.ps1 -Target All -Publish` produces a self-contained Windows x64 desktop directory/ZIP and a separate signed Android APK. Artifacts live under artifacts/releases/<version>/desktop and android, with the desktop ZIP at the version root. -Target Desktop and -Target Android build independently. Runtime keys/databases remain outside artifacts. Users do not need a .NET SDK, Node.js or a source checkout. `Build-Android.ps1` builds/lints Android and signs using a local ignored key; its private key/password never enter either package. Preserve that signing identity for upgrade compatibility. An Inno Setup installer, Windows startup settings, GitHub release checks, and a separate self-contained updater process are implemented. The updater now stages beside the install, passes restart health/version arguments, and attempts rollback; a real installed upgrade/failure-injection run is still required. Release publishing verifies that the tag and remote branch identify the commit used for the artifacts. Successful compilation does not establish upgrade correctness. A Windows code-signing service and cloud deployment are not implemented.

Runtime state remains in the user's LocalAppData directory across artifact replacement. Artifacts are versioned; do not deploy an unqualified latest tag. Application CI is not implemented; any future CI must use short-lived/federated authentication. External tunnel provisioning/DNS remain external infrastructure configuration, not application secrets.

- `src/PocketAgent.Server`: API, provider protocol, policy mapping, authentication, SQLite, timing and scheduler.
- `src/PocketAgent.Desktop`: native control/chat UI, Wi-Fi setup and connector lifecycle.
- `src/PocketAgent.Android`: native multi-server client, encrypted vault, transport and debug-only instrumentation.
- `scripts`: repeatable builds, signing, publishing, connector acquisition and local launch.
- `tests`: isolated deterministic protocol/security/scheduler checks and emulator tests. Live inference requires explicit opt-in.

See [setup and verification](SETUP.md) for commands, artifacts and remaining acceptance checks.
