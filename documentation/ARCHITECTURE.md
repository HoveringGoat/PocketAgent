# Runtime architecture

## Components and ownership

PocketAgent 0.1.4 has a native Windows WPF desktop/server app and a native Android client built with Android platform widgets. There is no browser client or WebView. The desktop embeds an ASP.NET Core relay, owns one local Codex app-server subprocess over standard input/output, and stores local metadata in SQLite. Android uses foreground HTTPS snapshot polling. The retained SignalR API is compatible with earlier relay consumers but is not required by either native UI.

Only conversations created by PocketAgent and registered in this host's runtime database are exposed. Existing IDE-owned sessions are not attached. The configured repository supplies the default folder; each new conversation can select a different existing local directory. A phone can pair with several different desktop hosts. Provider execution, repository access, provider credentials, and provider-owned transcript history remain on the desktop.

Desktop administration calls local services in-process. The network API exposes paired conversation operations, usage, schedules, and folder selection, not host permission settings, executable settings, pairing-code generation, or device administration. All paired devices act as the same desktop owner across the host's PocketAgent conversations; separate user roles are not implemented. The approved multi-folder expansion allows authenticated devices to browse directory names and select existing folders on local drives accessible to the desktop account. This is owner access, not a per-repository access boundary. Directory browsing does not return file contents, create folders, or accept network/UNC/device paths. Conversation folders are immutable after creation and never rewrite the host's default folder. Provider sandbox/approval selection remains desktop-owned; workspace-write roots must use the selected conversation folder on every turn.

## Provider discovery and permissions

`CodexExecutableResolver` prioritizes an explicit executable override, then the highest installed stable VS Code `openai.chatgpt-*` extension's architecture-matching native binary, then a native CLI on PATH/npm locations. The default extension root is the current user's `.vscode/extensions`; `CodexExtensionsDirectory` can override it. No extension files are copied, changed, or redistributed. An already running provider process keeps its selected executable until restart. The model is never silently replaced.

`HostSettings.PermissionMode` is a desktop-owned startup setting:

| Value | Behavior |
| --- | --- |
| `inherit` | Omit policy overrides and use Codex settings. Default. |
| `ask` | Request workspace-write with restricted network access and on-request approvals. |
| `full-access` | Request danger-full-access and approval policy never. |

`CodexPermissions` applies an explicit selection to thread start/resume and each new turn. Steering retains the active turn's policy. Global Codex configuration, model, and reviewer are not rewritten. Managed provider restrictions remain authoritative. Provider rejection is surfaced without falling back to a weaker mode. The conversation snapshot distinguishes the selected mode from sandbox/approval fields reported by the provider. Old transcript reads do not resume execution or establish current permissions.

The native desktop selector is disabled while the host runs. Stop, save, and restart to change the mode. This changes PocketAgent-owned conversations, not a separate parent agent, IDE, or terminal session. Permissions determine command access; repository instruction files can still require a conversational planning approval.

## Authentication and device access

A desktop-generated six-digit code is valid for ten minutes and consumed once. It can be renewed locally without stopping work. Pairing is rate-limited per source address and globally; a proxy cannot evade the global cap by changing forwarded headers. Native `/api/devices/pair` returns a unique random bearer token. Only its SHA-256 hash is stored in SQLite. Device sessions expire after thirty days and can be individually revoked on the desktop. Both apps must use version 0.1.4 or later for new six-digit pairings; existing device tokens survive the upgrade.

All protected operations authenticate on every request. Native mutations require `X-PocketAgent: 1`. Any supplied browser Origin must exactly match a configured origin; CORS is not enabled. The legacy cookie pairing/logout path remains for API compatibility checks, with HttpOnly, SameSite Strict and HTTPS Secure cookies. There is no browser UI behind it.

Android stores saved server names, origins and tokens in an AES-GCM encrypted vault using a non-exportable Android Keystore key. Tokens are tied to their exact origin; changing or adding an address requires pairing at that address. Redirects are rejected before credentials can be forwarded. Each host has separate selection, draft and uncertain-delivery state. Backups and device transfers exclude app data. Draft text is private app-local state and is not packaged. A revoked server returns to pairing without deleting other saved server connections.

## Network exposure and trust

The initial listener is loopback HTTP at `127.0.0.1:5147`. It is reachable only on the desktop. Loopback is the origin for local development and internet connectors; cleartext LAN listening is rejected. Host validation accepts only the exact listener authority and, when configured, the exact HTTPS `PublicOrigin` authority. Forwarded headers are not used to authorize identities or weaken transport checks.

### Direct Wi-Fi

Desktop **Set up Wi-Fi HTTPS** enumerates private IPv4 interfaces and creates a CA/server certificate for the selected address. The PFX remains under the private runtime directory; only the public CA certificate goes to the phone. Android accepts platform-trusted certificates and CAs explicitly installed by its owner. It never disables hostname or chain verification. This deliberate local-CA support is documented beside the narrow Android lint suppression.

The setup action saves the listener/certificate settings and opens the certificate directory. It does not modify firewall rules, trust stores, or routers. Windows private-network firewall access may be needed; guest-network peer isolation can still prevent access. A changed IP requires a matching certificate. On Windows the HTTPS loader uses the current user's key store for Schannel compatibility.

### Internet access (historical tunnel implementation, before 0.1.8)

Before 0.1.8, the desktop package included checksum-verified cloudflared 2026.10.7 and supervised a hidden connector child. That UI/helper and packaging dependency have been removed. The following tunnel details describe older packages only; current setup uses automatic direct HTTPS below.

**Named tunnel (optional existing transport):** a user-owned Cloudflare account/domain and named outbound tunnel provide a stable HTTPS hostname. Its ingress forwards to the loopback relay. PocketAgent can generate the local config from an existing tunnel UUID and credential file, but does not provision DNS, create accounts or copy secrets into artifacts. Cloudflare owns the external edge; the user owns tunnel/DNS configuration and account costs; this repository owns application code, packaging and connector lifecycle. This is not the required onboarding model for the distributable app.

**Temporary trial:** Quick Tunnel needs no account/domain and produces a temporary HTTPS `trycloudflare.com` address. The connector parser accepts only that exact authority, never wildcard hosts. The runtime public origin updates to that address and is cleared on connector stop. The address changes on restart and has no uptime guarantee; saved clients must pair at a new origin. Foreground polling avoids Quick Tunnel's SSE limitation. This is a documented development exception, not the stable hosting model.

Cloudflare terminates public TLS and can process relayed conversation data. This is not end-to-end encryption through the edge. Provider credentials never cross it. A user-managed HTTPS reverse proxy such as Caddy is an alternative for users who also manage DNS, inbound reachability and certificates. Public-origin proxy mode requires a loopback backend. Do not add a public listener or trust arbitrary proxy headers to make a connection work.

### Direct internet (IP and port)

The user requires conversation traffic to travel directly between their phone and desktop. A required personal domain, centralized PocketAgent hosting, and third-party peer relays (even encrypted) were explicitly rejected. Version 0.1.4 implements direct IPv4 HTTPS with manual router/firewall configuration and diagnostics. Existing optional HTTPS/tunnel paths remain available; do not start them for the direct mode. Do not select libp2p relay networks, Tor, or a hosted PocketAgent relay as the product default.

[Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/concepts/) works because the desktop connects outward to a publicly reachable Cloudflare edge, which relays incoming client traffic. It is not direct hole punching. Reimplementing that architecture still requires an intermediate public host and would violate the direct-only requirement.

Desktop **Set up direct internet (IP + port)** chooses a private LAN interface, takes the router's public IPv4 and external TCP port, and creates a private CA/server certificate with SANs for both IPs. `HostSettings.DirectOrigin` is the exact advertised HTTPS authority; `Origin` remains the internal HTTPS listener. `DirectOrigin` is mutually exclusive with proxy-mode `PublicOrigin` and requires HTTPS. Cleartext and private/CGNAT WAN inputs are rejected. The server accepts only the exact internal and advertised authorities; forwarded headers and arbitrary Host/Origin values remain untrusted. The external and internal ports can differ. Router/firewall changes are manual and never performed by installation, startup or the setup wizard. No account, domain, rendezvous, hole punching or traffic relay is used. IPv6 and automatic router mapping are not implemented.

Version 0.1.5 adds explicit **Detect public IP** during setup. `PublicAddressLookup` queries the fixed IPv4 HTTPS endpoint [documented by ipify](https://www.ipify.org/), `https://api.ipify.org?format=json`, only when clicked. This optional address-discovery request exposes the public source IP and ordinary TLS/HTTP connection metadata to that service; it does not relay conversations or send device/provider credentials or pairing codes. A separate client disables redirects, cookies, and proxy use. TLS verification remains enabled. Reads have an eight-second deadline and 1 KB response limit; malformed, non-IPv4, private/CGNAT and failed responses are rejected with manual-entry fallback. Opening/closing setup does not perform a lookup; closing cancels one already requested. Detection never overwrites text edited during the pending request and never changes certificates, host settings or firewall/router rules by itself. No remote lookup API is exposed. Detection identifies the outbound/VPN address and does not establish controllable public router reachability; conversation connections remain direct. Local-only connection diagnostics remain independent of this optional internet request.

The user forwards external TCP to the selected private desktop IP/listener port and allows Windows Firewall access. Reserve the LAN IP. Transfer the public CA certificate over a trusted channel and install it in Android; keep PFX/private keys on the desktop. Android continues full certificate chain and IP-name verification. A domain is not required. Changing the public IP requires certificate/address setup again; changing origins requires fresh pairing. A desktop behind carrier-grade NAT may need a public IPv4 from its ISP; double NAT requires both routers to be configured. No silent relay fallback is allowed.

`ConnectivityDiagnostics.Check` (desktop **Devices > Connection diagnostics**, or headless `--diagnose`) verifies the listener, public-IP certificate identity, custom local CA chain, exact public Host and API response using a local socket connection. It makes no internet probe, sends no credentials, does not disable TLS checks, and does not claim that router/firewall or external reachability is verified. It reports the exact TCP forwarding target, CA SHA-256 fingerprint, expiration, CGNAT/double-NAT caveats, and a cellular acceptance step. A certificate/public-IP mismatch fails. Android's pairing page **Test connection** makes an unauthenticated HTTPS metadata request; on cellular it tests the actual outside route before pairing. Bare `IP:port` input defaults to HTTPS. Error text distinguishes certificate verification from reachability. The six-digit code grants device access after TLS trust; it is not a discovery address or encryption key. Revocation and uncertain-delivery non-replay apply unchanged.

## Conversations, steering and recovery

`Conversations` serializes state mutations. Exactly one provider turn runs per conversation. Idle input starts a new turn; additional active input uses `turn/steer` with the sender's expected turn ID. A stale ID is rejected and never silently converted into a new turn. An unscoped second turn is rejected. Steering does not answer an approval, modify policy, or cancel work.

Both native clients leave the composer editable during submission and clear only the exact acknowledged draft. Typing after Send is preserved. Neither prompts nor approval decisions are automatically replayed. Uncertain native delivery is persisted per origin/conversation and requires the user to review before resubmitting. Reconnection refreshes authoritative state; phone disconnection does not stop desktop execution. Provider disconnect clears pending controls and requires a host restart.

Each conversation retains its working directory and optional selected model in SQLite. The host default is only a creation fallback. Create/resume/turn requests explicitly use the stored directory; workspace-write policy roots follow that directory. An idle conversation can select a model from the live, paginated provider catalog. It is sent on subsequent starts/resumes/turns without rewriting global Codex config or another conversation's model. Active, uncertain, or disconnected work blocks model changes; steering has no model/directory overrides. Scheduled messages use the model selected at dispatch. Omitting a model during creation preserves Codex settings. Catalog presence is not proof of inference entitlement. The integration follows the [official Codex app-server documentation](https://learn.chatgpt.com/docs/app-server).

Archive is a reversible PocketAgent registry state, not provider history deletion. It removes the tab from all devices and is blocked during active/unconfirmed work or an in-flight scheduled dispatch. SQLite atomically marks the archive and cancels pending schedules. The scheduler cannot claim or requeue work for an archived conversation. Archived history is readable; mutation/send/schedule operations require restore. Restoring never requeues canceled jobs. An additive database migration preserves old conversation directories and device credentials; all conversations registered in the same runtime are available regardless of the current default directory.

Codex standard input/output/error streams explicitly use UTF-8. Native Windows launches otherwise can decode raw non-ASCII JSON using the Windows default encoding, corrupting punctuation before HTTP serialization. Android already reads/writes HTTP JSON with UTF-8. No heuristic character substitutions are applied. User messages have trailing-edge bubbles; assistant prose uses the plain transcript background in both apps. Local time grouping still applies.

Android transcript updates use coordinate scrolling rather than `ScrollView.fullScroll`, which can move focus to a newly added selectable message. Incoming output must preserve the composer's focus, cursor/selection, draft and keyboard state; polling must not refocus the composer if the user is interacting elsewhere. The focused native regression checks a draft and a cursor in its middle while a delayed assistant response arrives.

Desktop `Transcript` sets inherited `TextElement.Foreground` to light green `#C1DAA6`, preventing user/assistant/tool text and approval descriptions from inheriting the tab theme's black foreground. The desktop root also applies the readable text color to static settings/device labels. This is scoped to the native app; explicit timestamp/error colors and control styles for buttons/text inputs take precedence. The transcript renderer keeps a bounded recent view (400 items and 300,000 characters) so a tool-heavy history cannot grow the WPF visual tree without limit; complete history remains in Codex. `tests/PocketAgent.DesktopChecks` renders the real native hierarchy with isolated settings and asserts effective brush values and the large-transcript budget; a plain source check would miss the inheritance problem.

Supported command/file approvals are restricted to available one-time decisions. Broader grants, unsupported host interactions and unknown provider fields are not automatically approved. Questions require explicit answers. Pending requests retain their original JSON-RPC and conversation identity; resolved requests cannot be answered again.

Codex owns transcripts. SQLite stores PocketAgent references, device hashes, timing metadata and schedules. Live message timestamps are persisted on first observation and restored from that metadata. Provider turn times support work durations, but are not invented as individual message times for older history. Unknown historical message times remain unknown. Turn starts/completions/durations are retained separately and surfaced as active elapsed time or completed work duration. Clients group adjacent chat times by local minute. Status/context controls remain between the scrolling transcript and composer. Session navigation uses top tabs.

## Automatic public IP certificates (0.1.8)

The direct setup wizard uses pinned Certes 4.1.0 for RFC 8738 IP identifiers, HTTP-01 and the `shortlived` profile. It tests staging before production, with separate persisted account keys per environment/IP. Owner-only directory ACLs protect keys/PFX; atomic replacement preserves the prior PFX on issuance failure. Setup accepts the CA agreement locally. There is no remote configuration/issuance API, no bundled credentials and no central PocketAgent service. CA contact reveals the public IP and public certificate, not chats; issued certificates are publicly logged.

`AcmeChallengeListener` is a separate slim Kestrel host on an explicit interface and separate LAN port (default 5080). Router public TCP 80 must forward there. It accepts only GET with the exact public-IP Host and active token path, no query/body. All other paths (including chat/pairing) fail. It has connection/header/body/time/rate limits and no file serving, proxy or app services. It closes after authorization, on failure and on cancellation. Validation sources cannot be IP-allowlisted. Challenge content is public; limiting this responder's functionality is the exposure mitigation, not a secret-token authentication claim.

`AutomaticCertificates` renews halfway through lifetime, checks every five minutes while the host runs, and backs off six hours after failure. It validates public chain/IP/SAN/expiry before writing production PFX. The TLS selector/context supplies the current certificate and intermediates for new connections; retained previous certificates protect in-flight handshakes until shutdown. Host ownership precedes renewal. Setup acquires the runtime lease too. Keys live outside artifacts; no CA-root install or TLS bypass is required on Android. Public-IP changes are manual reconfiguration; no auto-discovery during chat/startup. Renewal does not run while the app is closed or desktop asleep. Invalid/expired TLS fails closed. Only HTTP-01 is implemented; no 443 alternative or automatic firewall/router changes.

The native theme now gives TextBlock, tabs, dropdown popup/items, list selection, buttons, password inputs and tooltips explicit matching colors; custom templates avoid Windows light theme overrides. Settings no longer exposes tunnels or proxy configuration. The removed desktop connector helper and packaging downloader are obsolete; existing private runtime files remain untouched. The manual Wi-Fi/private-CA fallback lives under Advanced certificate settings.

Version 0.1.9 removes the remaining Windows light-theme scrollbar tracks (observed `#F0F0F0` in a native regression). Scrollbars now have explicit dark track/thumb templates for both orientations. App-owned windows request dark native title bars through DWM (supported Windows versions; failures fall back to OS chrome). `AppDialogs` replaces native white MessageBox prompts with styled WPF dialogs, preserving explicit confirmation and treating dismissal as non-approval. OS-owned folder pickers remain controlled by Windows. Native tests check effective brushes, rendered bright-surface coverage, and explicit Yes versus close behavior; rendered previews are generated under `.local/desktop-theme-screen-*.png`.

Optional existing-Caddy integration routes only the public-IP HTTP challenge path to the isolated desktop listener; see setup. Caddy must preserve Host and path, retain its existing domain routes, and remain available for renewal. This changes validation routing only; chat stays direct. No home-server configuration is changed by PocketAgent or development tools. The standard HTTP-01 public-port requirement still applies.

Verified: focused native screen/dropdown checks; a local ACME HTTP fixture exercises IP/profile orders, challenge validation and SAN CSR/certificate download, failure preservation, listener shutdown, expiry timing and rejection of untrusted certificates. Live staging/production issuance and physical-phone acceptance still require the user's port forwarding and end-to-end verification. No production certificate has been requested by development tools.

## Usage and scheduled messages

`ProviderUsage` reads `account/rateLimits/read` through the same provider connection and accepts rate-limit updates. It exposes only normalized remaining percentage, duration, reset time and availability. Account IDs, plan/credit details and upsell payloads stay private. Five-hour and weekly labels require reported 300-minute and 10080-minute windows; unsupported/missing data is shown as unavailable. Read results are briefly cached. No credits or earned resets are purchased/consumed by PocketAgent.

`ScheduledMessages.Send` checks known exhausted windows. A blocked prompt is persisted and acknowledged as queued, with the reported reset time or an explicit unknown-reset state. The latest reset among exhausted windows is used. A later provider `usageLimitExceeded` failure also defers an accepted prompt only when no work is known to have executed. It never automatically repeats partial work or an uncertain submission.

Manual schedules accept an explicit UTC timestamp converted from the client's chosen local date/time. Jobs have requested time, next attempt, reason and status. The worker waits for host readiness and an idle, confirmed conversation. Active turns and unanswered approvals postpone dispatch; schedules never become implicit steering or approval decisions. All registered folders share this host's queue; each job uses its own conversation's folder. Archived conversations cannot dispatch. Expired/revoked devices cancel their pending jobs; desktop-created jobs have no device expiry dependency.

Dispatch claims a pending job atomically in SQLite before contacting Codex. A confirmed acceptance marks it submitted; this is not a promise of successful agent completion. Known provider rejections become failed/pending as appropriate. Lost acknowledgements become uncertain. A host restart converts in-flight dispatching jobs to uncertain and never automatically replays them. A per-data-directory host lease is acquired before constructing/migrating the database, as well as before dispatch: attempting to start a new version while the old host runs must not change its schema. Missed due times are reconsidered when the desktop runs again. There are no OS wake timers or cloud workers: a sleeping/stopped desktop cannot dispatch.

## Build, distribution and change points

`scripts/Build.ps1 -Publish` produces a self-contained Windows x64 desktop directory/ZIP, with compiled relay, connector, setup docs and the signed Android APK. Users do not need a .NET SDK, Node.js or a source checkout. `Build-Android.ps1` builds/lints Android and signs using a local ignored key; its private key/password never enter either package. Preserve that signing identity for upgrade compatibility. No installer registration, automatic startup, code-signing service, cloud deployment or automatic update service is implemented.

Runtime state remains in the user's LocalAppData directory across artifact replacement. Artifacts are versioned; do not deploy an unqualified latest tag. Application CI is not implemented; any future CI must use short-lived/federated authentication. External tunnel provisioning/DNS remain external infrastructure configuration, not application secrets.

- `src/PocketAgent.Server`: API, provider protocol, policy mapping, authentication, SQLite, timing and scheduler.
- `src/PocketAgent.Desktop`: native control/chat UI, Wi-Fi setup and connector lifecycle.
- `src/PocketAgent.Android`: native multi-server client, encrypted vault, transport and debug-only instrumentation.
- `scripts`: repeatable builds, signing, publishing, connector acquisition and local launch.
- `tests`: isolated deterministic protocol/security/scheduler checks and emulator tests. Live inference requires explicit opt-in.

See [setup and verification](SETUP.md) for commands, artifacts and remaining acceptance checks.
